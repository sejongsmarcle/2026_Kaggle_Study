# 캐글 과제2

## 1. 회귀(Regression)와 분류(Classification)는 무엇이 다르며, 어떤 문제를 풀고 있는지는 무엇을 보고 판단할 수 있는가?

회귀는 연속적인 숫자값을 예측하는 문제임.  
예: 집값, 보험료 예측

분류는 정해진 클래스 중 하나를 예측하는 문제임.  
예: 생존 여부, 스팸 여부

숫자 자체를 예측하면 회귀, 어떤 종류에 속하는지를 예측하면 분류라고 보면 됨.

---

## 2. 분류 모델에서 Accuracy가 높다고 해서 항상 좋은 모델이라고 할 수 없는 이유는 무엇인가? 데이터의 한쪽 클래스가 훨씬 많은 경우를 예로 들어 설명해보자.

Accuracy는 전체 데이터 중 맞춘 비율임.

예를 들어 정상 95개, 이상 5개일 때 전부 정상이라고 예측해도 Accuracy는 95%가 나옴.  
하지만 이상 데이터는 하나도 찾지 못한 거라 좋은 모델이라고 보기 어려움.

이런 경우 Precision, Recall, F1-score 같은 지표도 같이 봐야 함.

---

## 3. 데이터를 StandardScaler 등의 방법으로 스케일링하는 이유는 무엇인가? 모든 머신러닝 모델에서 스케일링이 똑같이 중요한지도 함께 설명해보자.

특성마다 값의 크기 차이가 너무 크면 특정 특성이 모델에 더 큰 영향을 줄 수 있어서 스케일링함.

예를 들어 나이는 20~60 정도인데 연봉은 수천만 단위라면 값의 크기 차이가 큼.

KNN, SVM, 선형 모델 등은 스케일링의 영향을 많이 받지만 Random Forest 같은 트리 기반 모델은 상대적으로 영향이 적음.

---

## 4. 데이터 누수(Data Leakage)란 무엇이며, 데이터 누수가 발생하면 Validation 성능이 실제보다 높게 나올 수 있는 이유는 무엇인가? 누수가 발생할 수 있는 상황도 한 가지 예를 들어보자.

데이터 누수는 학습할 때 원래 알면 안 되는 Validation이나 Test 데이터의 정보가 들어가는 경우임.

예를 들어 전체 데이터의 평균으로 결측치를 채운 다음 Train/Validation으로 나누면 Validation 정보도 전처리에 사용될 수 있음.

이러면 모델이 미리 정보를 본 것과 비슷해서 Validation 성능이 실제보다 높게 나올 수 있음.

---

## 5. 파라미터(Parameter)와 하이퍼파라미터(Hyperparameter)는 어떻게 다른가? 하이퍼파라미터 값을 바꾸면 모델의 성능이 달라질 수 있는 이유도 설명해보자.

파라미터는 모델이 학습하면서 데이터로부터 직접 구하는 값임.  
예: 선형회귀의 가중치(w), 편향(b)

하이퍼파라미터는 학습 전에 사람이 설정하는 값임.  
예: Random Forest의 `n_estimators`, `max_depth`

하이퍼파라미터에 따라 모델의 복잡도나 학습 방식이 달라지기 때문에 성능이나 과적합 정도도 달라질 수 있음.

---

## 6. Random Forest와 Gradient Boosting(XGBoost, LightGBM 등)은 모두 여러 Decision Tree를 사용하는데, 트리를 만드는 방식에는 어떤 차이가 있는가?

Random Forest는 여러 트리를 각각 독립적으로 학습한 다음 결과를 합치는 방식임.

Gradient Boosting은 앞의 트리가 틀린 부분을 다음 트리가 보완하면서 순서대로 학습함.

즉 Random Forest는 여러 트리를 따로 만들고, Gradient Boosting은 이전 오차를 계속 보완하는 방식임.

---

## 7. GridSearchCV와 같은 하이퍼파라미터 탐색 방법을 사용하는 이유는 무엇인가? 가능한 값을 무조건 많이 탐색하면 항상 더 좋은 모델을 찾을 수 있는지도 생각해보자.

하이퍼파라미터 값에 따라 모델 성능이 달라질 수 있어서 좋은 조합을 찾기 위해 사용함.

GridSearchCV는 여러 조합을 자동으로 비교하고 교차검증을 통해 좋은 값을 찾아줌.

값을 무조건 많이 넣으면 계산 시간이 오래 걸리고 필요 없는 범위까지 탐색할 수 있어서 적당한 범위를 정하는 게 좋음.

---

## 8. Train 또는 Validation에서는 성능이 좋았지만 실제 Test 데이터에서 성능이 크게 떨어졌다면 어떤 원인을 의심할 수 있는가? 과적합, 데이터 누수, Train/Test 데이터 차이 등의 개념을 활용하여 설명해보자.

가장 먼저 과적합을 의심할 수 있음.

Train 데이터에 너무 맞게 학습되면 새로운 Test 데이터에서 성능이 떨어질 수 있음.

또 데이터 누수가 있으면 Validation 성능이 실제보다 높게 나올 수 있고, Train과 Test 데이터의 분포가 다른 경우에도 성능 차이가 날 수 있음.
