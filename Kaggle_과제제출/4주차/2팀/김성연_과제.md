# 3주차 개념 문제
> 머신러닝의 주요 개념과 각 개념에 대한 해설

## 1. 회귀(Regression)와 분류(Classification)는 무엇이 다른가?

회귀와 분류는 **예측하려는 정답의 형태**가 다르다.

- **회귀**는 집값, 기온, 매출처럼 수치의 크기를 예측하는 문제이다.
- **분류**는 스팸 여부, 동물의 종류처럼 데이터가 어떤 범주에 속하는지 예측하는 문제이다.

어떤 문제인지는 입력 데이터보다 **예측 대상인 타깃(target)의 의미**를 보고 판단해야 한다. 예를 들어 같은 주택 데이터를 사용하더라도 집값을 예측하면 회귀이고, 주택 유형을 아파트·빌라·단독주택으로 예측하면 분류이다.

정답이 숫자로 표현되어 있다고 무조건 회귀는 아니다. 정상 메일을 0, 스팸 메일을 1로 표시했다면 이 숫자는 크기가 아니라 범주를 뜻하므로 분류 문제이다.

## 2. 분류 모델에서 Accuracy가 높다고 항상 좋은 모델이라고 할 수 없는 이유는 무엇인가?

Accuracy(정확도)는 전체 데이터 중에서 모델이 정답을 맞힌 비율이다.

**Accuracy = 올바르게 예측한 데이터 수 / 전체 데이터 수**

하지만 클래스별 데이터 수가 크게 차이 나는 **클래스 불균형** 상황에서는 정확도만으로 모델의 성능을 판단하기 어렵다.

예를 들어 거래 1,000건 중 정상 거래가 990건이고 사기 거래가 10건이라고 해보자. 모델이 모든 거래를 정상이라고 예측하면 정확도는 99%이다. 그러나 사기 거래는 단 한 건도 찾아내지 못하므로, 사기 탐지 목적에는 도움이 되지 않는다.

따라서 문제의 목적에 맞춰 다른 지표도 함께 확인해야 한다.

- **Precision(정밀도)**: 사기라고 예측한 거래 중 실제 사기인 비율
- **Recall(재현율)**: 실제 사기 거래 중 모델이 찾아낸 비율
- **F1-score**: 정밀도와 재현율의 조화평균

사기 거래를 놓치는 것이 큰 문제라면 재현율이 특히 중요하다. 반대로 정상 거래를 사기로 잘못 판단하는 비용도 크다면 정밀도 역시 함께 고려해야 한다.

## 3. 데이터를 StandardScaler 등의 방법으로 스케일링하는 이유는 무엇인가?

스케일링은 특성마다 다른 값의 범위를 조정하는 과정이다.

예를 들어 나이는 수십 단위이고 연봉은 수천만 단위일 수 있다. 이 상태에서 거리를 계산하면 연봉의 숫자 차이가 나이의 차이보다 훨씬 크게 반영될 수 있다. 이는 연봉이 실제로 더 중요한 특성이어서가 아니라 단위가 다르기 때문에 생기는 문제이다.

StandardScaler는 각 특성에서 평균을 빼고 표준편차로 나누어, 학습 데이터에서 평균이 0이고 분산이 1이 되도록 변환한다. 단, 값이 모두 같은 특성은 예외이다.

**변환값 = (원래 값 - 학습 데이터의 평균) / 학습 데이터의 표준편차**

스케일링은 거리 계산에서 특정 특성이 과도하게 영향을 주는 것을 줄이고, 최적화 과정이나 규제가 특성의 단위에 민감하게 반응하는 문제를 완화할 수 있다.

다만 모든 모델에서 똑같이 중요한 것은 아니다.

- **KNN, SVM**: 거리나 내적을 활용하므로 스케일링이 중요한 경우가 많다.
- **신경망, 규제를 사용하는 선형 모델**: 학습의 안정성과 규제의 균형을 위해 도움이 되는 경우가 많다.
- **Decision Tree, Random Forest, 트리 기반 Gradient Boosting**: 주로 특성값의 순서를 기준으로 분기하므로 일반적으로 스케일링의 영향이 작다.

또한 스케일러는 Train 데이터에만 `fit`하고, Validation과 Test에는 같은 스케일러로 `transform`해야 한다.

## 4. 데이터 누수(Data Leakage)란 무엇인가?

데이터 누수는 **실제 예측 시점에는 사용할 수 없는 정보가 모델의 학습이나 선택 과정에 들어가는 현상**이다.

Validation 데이터는 처음 보는 데이터에 대한 성능을 추정하는 데 사용한다. 그런데 이 데이터의 정보가 학습에 미리 반영되면, 완전히 새로운 데이터로 평가하는 조건이 깨진다. 그 결과 Validation 성능이 실제 일반화 성능보다 높게 나올 수 있다.

예를 들어 전체 데이터에 StandardScaler를 먼저 적용한 뒤 Train과 Validation으로 나누면, Validation 데이터의 평균과 분산 정보가 학습 데이터의 변환에 이미 반영된다. 이는 전처리 과정에서 발생하는 데이터 누수이다.

이를 방지하려면 다음 순서를 따라야 한다.

1. 데이터를 Train과 Validation으로 나눈다.
2. Train 데이터로만 스케일러를 학습한다.
3. 학습한 스케일러로 Train과 Validation을 각각 변환한다.
4. 모델을 학습하고 평가한다.

교차 검증에서도 각 학습 폴드 안에서만 전처리를 학습해야 하며, 이를 위해 `Pipeline`을 활용할 수 있다.

## 5. 파라미터(Parameter)와 하이퍼파라미터(Hyperparameter)는 어떻게 다른가?

두 개념은 **값이 결정되는 방식**이 다르다.

- **파라미터**는 모델이 학습 데이터를 통해 학습하는 값이다.
- **하이퍼파라미터**는 학습 방식이나 모델 구조를 정하기 위해 외부에서 설정하는 값이다.

예를 들어 선형 회귀의 가중치와 절편은 파라미터이다. 반면 Decision Tree의 최대 깊이인 `max_depth`, KNN의 이웃 수인 `n_neighbors`, Gradient Boosting의 `learning_rate`는 하이퍼파라미터이다.

하이퍼파라미터를 바꾸면 모델의 복잡도나 학습 과정이 달라지므로 성능도 달라질 수 있다. 예를 들어 트리의 깊이가 너무 얕으면 데이터의 패턴을 충분히 학습하지 못해 과소적합이 발생할 수 있다. 반대로 너무 깊으면 학습 데이터의 잡음까지 반영하여 과적합이 발생할 수 있다.

따라서 하이퍼파라미터는 학습 데이터에 잘 맞는지만 보기보다, 새로운 데이터에서도 좋은 성능을 내는지를 기준으로 선택해야 한다.

## 6. Random Forest와 Gradient Boosting은 트리를 만드는 방식이 어떻게 다른가?

두 방법 모두 여러 Decision Tree의 예측을 결합하지만, **각 트리가 다른 트리와 어떤 관계로 학습되는지**가 다르다.

### Random Forest

Random Forest는 일반적으로 데이터를 중복을 허용해 무작위로 뽑고, 각 분기에서 일부 특성만 후보로 고려하여 다양한 트리를 만든다.

각 트리는 다른 트리의 오차를 보완하는 방식으로 학습하지 않으므로 병렬로 학습할 수 있다. 회귀에서는 주로 예측값을 평균 내고, 분류에서는 투표나 클래스 확률의 평균을 이용해 최종 예측을 결정한다.

다양한 트리의 결과를 결합하여 개별 트리의 불안정성을 줄이는 것이 핵심이다.

### Gradient Boosting

Gradient Boosting은 트리를 순차적으로 추가한다. 새 트리는 **현재까지 결합된 모델의 손실을 줄이는 방향**으로 학습된다.

제곱오차를 사용하는 회귀 문제에서는 현재 예측과 실제 정답의 차이인 잔차를 학습한다고 이해할 수 있다. 더 일반적으로는 손실 함수의 음의 그래디언트 등을 이용한다.

XGBoost와 LightGBM은 이러한 Gradient Boosting 계열의 대표적인 모델이다.

정리하면 Random Forest는 독립적으로 학습한 여러 트리의 예측을 모으고, Gradient Boosting은 앞서 만든 모델의 부족한 부분을 보완하도록 트리를 차례로 추가한다.

## 7. GridSearchCV와 같은 하이퍼파라미터 탐색 방법을 사용하는 이유는 무엇인가?

하이퍼파라미터의 적절한 값은 데이터와 문제에 따라 달라지므로, 여러 후보를 체계적으로 비교하기 위해 탐색 방법을 사용한다.

GridSearchCV는 지정한 하이퍼파라미터 조합을 모두 평가하고, 교차 검증에서 선택한 평가 지표가 가장 좋은 조합을 찾는다. 한 번의 데이터 분할에만 의존하는 것보다 여러 분할에서의 성능을 비교할 수 있다는 장점이 있다.

하지만 가능한 값을 무조건 많이 탐색한다고 실제 성능이 항상 좋아지는 것은 아니다.

- 후보 조합이 늘어날수록 학습 시간과 계산 비용이 증가한다.
- 같은 검증 데이터를 기준으로 너무 많은 후보를 비교하면, 우연히 높은 점수를 받은 조합을 선택할 가능성이 커진다.
- 평가 지표나 데이터 분할 방식이 문제에 맞지 않으면, 탐색을 늘려도 실제 목적에 맞는 모델을 찾기 어렵다.

따라서 의미 있는 범위와 적절한 평가 지표를 정하는 것이 중요하다. 탐색 공간이 넓다면 RandomizedSearchCV 같은 방법도 고려할 수 있다.

최종 Test 데이터는 하이퍼파라미터 선택에 사용하지 않고, 모델 선택이 끝난 뒤 최종 평가에 사용해야 한다.

## 8. Train 또는 Validation에서는 성능이 좋았지만 Test 성능이 크게 떨어졌다면 어떤 원인을 의심할 수 있는가?

### 과적합

모델이 일반적인 패턴보다 Train 데이터의 세부적인 특징이나 잡음을 지나치게 학습했을 수 있다. 이 경우 Train 성능은 높지만 새로운 데이터에서는 성능이 떨어진다.

Validation 성능을 보면서 모델과 하이퍼파라미터를 반복해서 수정했다면, 모델 선택 과정이 Validation 데이터에 과도하게 맞춰졌을 가능성도 있다.

### 데이터 누수

전처리에 Validation 정보를 사용했거나, 같은 대상의 중복 데이터가 Train과 Validation에 나뉘어 들어갔을 수 있다.

이 경우 Validation 성능은 높게 측정되지만, 그런 정보가 없는 Test 데이터에서는 성능이 낮아질 수 있다.

### Train과 Test의 데이터 차이

학습 데이터와 실제 평가 데이터의 분포가 다를 수 있다.

예를 들어 과거의 구매 기록으로 학습했는데 Test 데이터가 유행이 바뀐 이후의 구매 기록이라면, 기존에 학습한 관계가 더 이상 잘 맞지 않을 수 있다. 수집 지역, 사용자 집단, 측정 환경의 차이도 영향을 줄 수 있다.

### 평가·전처리 과정의 문제

Train과 Test에 서로 다른 전처리를 적용했거나, 특성의 순서 또는 범주 인코딩이 달라졌을 수 있다. Test 데이터가 너무 적어서 성능 추정의 변동이 큰 경우도 고려해야 한다.

따라서 Train·Validation·Test의 성능 차이를 비교하고, 데이터 분할 방식, 중복 여부, 전처리 과정, 데이터 분포를 차례로 확인해야 한다. 실제 사용 환경이 시간에 따라 달라지는 문제라면 시간 순서에 맞춘 검증도 필요하다.
