기존 코드는 EDA+전처리는 탄탄했지만 모델 학습이 아예 없었고, 인코딩 방식과 제출 준비(PassengerId)에 허점이 있었어요. 개선판은 그 구멍들을 메우고 파생변수를 추가해서, 실제로 캐글에 제출 가능한 완결된 파이프라인으로 만든 겁니다.

1. 이진 분류인 이유
정답이 생존(1)/사망(0) 딱 두 개뿐이라서.

2. 그래디언트 부스팅이 더 좋은 이유
트리 하나가 틀린 부분을 다음 트리가 계속 보완해가는 방식이라, 트리 하나만 쓰는 것보다 정교해짐.

3. Validation이 필요한 이유
Train으로 학습하고 Train으로 채점하면 "정답 미리 본 시험"이라 점수가 부풀려짐. 안 본 데이터로 확인해야 진짜 실력을 알 수 있음.

4. Early Stopping이 필요한 이유
계속 학습하면 어느 순간부터 train 데이터를 외우기 시작해서(과적합) 오히려 실전 성능은 떨어짐. 딱 좋은 지점에서 멈추는 것.

5. Accuracy 대신 Logloss를 쓰는 이유
Accuracy는 51%로 맞춘 거나 99%로 맞춘 거나 똑같이 취급함. Logloss는 "얼마나 확신 있게 맞췄는지"까지 평가함.

6. 확률로 주는 이유
0/1보다 정보량이 많고, 기준을 상황에 맞게 조절하거나 여러 모델을 평균 낼 때 유용함.

7. 범주형이라고 안 알려주면 생기는 문제
숫자로 바꾼 값(S=0, C=1, Q=2)을 모델이 "크기 순서"로 착각할 수 있음. 그냥 다른 종류일 뿐인데.

8. 파라미터 vs 하이퍼파라미터
파라미터 = 모델이 스스로 배우는 값. 하이퍼파라미터 = 학습 전에 사람이 정해주는 값(트리 개수 등).

9. K-Fold가 더 믿을 만한 이유
한 번만 나누면 우연히 쉬운/어려운 데이터가 걸릴 수 있음. 여러 번 나눠서 평균 내면 운의 영향이 줄어듦.

10. 앙상블이 더 안정적인 이유
모델 하나의 실수는 다른 모델들과 평균 내면 서로 상쇄되는 경향이 있어서, 극단적인 오류가 줄어듦.
