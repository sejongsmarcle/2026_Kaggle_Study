## 과제 2 개념문제 
### 1. 타이타닉 문제는 왜 “생존/사망”을 맞추는 이진 분류 문제인가?

타이타닉 데이터에서 우리가 예측하려는 값은 Survived이다.
이 값은 생존이면 1, 사망이면 0으로 두 가지 경우만 존재한다.

즉 모델이 여러 값 중 하나를 예측하는 것이 아니라,
생존(1) 또는 사망(0) 두 가지 중 하나를 선택해야 하기 때문에 이진 분류(Binary Classification) 문제라고 한다.



### 2. 트리(Decision Tree) 하나만 쓰는 것보다 여러 개의 트리를 순서대로 만들어가는 방식(그래디언트 부스팅)이 왜 더 성능이 좋은가?

Decision Tree 하나만 사용하면 첫 번째 트리가 잘못 판단한 부분을 그대로 가지고 있을 수 있다.

그래디언트 부스팅은 트리를 하나 만든 뒤 끝나는 것이 아니라,
앞의 트리가 틀린 데이터를 다음 트리가 보완하도록 계속해서 새로운 트리를 만든다.

예를 들어 첫 번째 트리가 어떤 승객을 잘못 예측했다면, 다음 트리는 그 틀린 부분을 더 잘 맞추도록 학습한다.

그래서

첫 번째 트리 → 틀린 부분 확인 → 다음 트리가 보완 → 다시 보완

하는 과정이 반복되면서 하나의 트리만 사용할 때보다 더 복잡한 패턴까지 학습할 수 있고 성능도 좋아질 수 있다.



### 3. Validation 데이터는 왜 따로 필요한가? Train 데이터만으로 모델 성능을 확인하면 뭐가 문제인가?

Train 데이터는 모델이 직접 공부한 데이터이다.

그런데 모델이 자신이 공부했던 문제로 다시 시험을 보면 당연히 점수가 높게 나올 가능성이 있다.

예를 들어 시험 문제와 정답을 미리 외운 학생에게 똑같은 문제로 시험을 보는 것과 비슷하다.

그래서 모델이 처음 보는 데이터에서도 잘 예측하는지 확인하기 위해 Train 데이터와 별도로 Validation 데이터를 사용한다.

Validation 성능을 보면 모델이 단순히 Train 데이터를 외운 것인지, 새로운 데이터에도 잘 적용되는지 확인할 수 있다.



### 4. Early Stopping은 왜 쓰는가? 계속 학습만 시키면 안 되는 이유는?

모델을 계속 학습한다고 해서 항상 성능이 좋아지는 것은 아니다.

처음에는 학습을 많이 할수록 중요한 패턴을 배우지만, 너무 오래 학습하면 Train 데이터의 특징이나 잡음까지 외우게 될 수 있다.

이렇게 학습 데이터에는 매우 잘 맞지만 새로운 데이터에서 성능이 떨어지는 현상을 **과적합(Overfitting)**이라고 한다.

Early Stopping은 Validation 성능이 더 이상 좋아지지 않으면 학습을 중단한다.

따라서 필요 이상으로 학습해서 과적합되는 것을 막고, 성능이 가장 좋은 시점의 모델을 사용할 수 있다.



### 5. 모델 성능을 확인할 때 정확도(Accuracy) 대신 Logloss를 쓰는 이유는 무엇인가?

Accuracy는 최종적으로 정답을 맞혔는지만 확인한다.

예를 들어 정답이 생존(1)이라고 했을 때,

모델 A: 생존 확률 0.51
모델 B: 생존 확률 0.99
두 모델 모두 최종 예측은 1이기 때문에 Accuracy에서는 똑같이 정답으로 처리된다.

하지만 두 모델의 확신 정도는 매우 다르다.

Logloss는 단순히 맞았는지만 보는 것이 아니라, 모델이 정답에 얼마나 높은 확률을 주었는지까지 평가한다.

특히 틀린 답을 매우 높은 확률로 확신하면 큰 패널티를 준다.

그래서 확률 예측의 품질까지 확인하고 싶을 때 Accuracy보다 Logloss가 더 유용하다.



### 6. 모델이 0/1이 아니라 확률(예: 0.73)로 예측 결과를 주는 이유는 무엇인가?

모델은 보통 먼저 각 결과가 나올 가능성을 확률로 계산한다.

예를 들어 모델이 어떤 승객에 대해 생존 확률을 0.73이라고 계산했다면,

이 승객이 생존할 가능성이 약 73%라고 판단했다

는 의미이다.

그다음 기준값을 0.5로 정했다면,

0.5 이상 → 생존(1)
0.5 미만 → 사망(0)
처럼 최종 결과를 결정할 수 있다.

확률을 제공하면 모델이 얼마나 확신하고 있는지도 알 수 있고, 상황에 따라 기준값을 바꿀 수도 있기 때문에 단순히 0과 1만 출력하는 것보다 더 많은 정보를 얻을 수 있다.



### 7. 숫자로 바꾼 범주형 변수(Sex, Embarked 등)를 모델에게 “이건 범주형이야”라고 다시 알려주지 않으면 어떤 문제가 생기는가?

범주형 변수는 숫자로 표현되어 있어도 실제 숫자의 크기에 의미가 없는 경우가 많다.

예를 들어 Embarked를

S = 0
C = 1
Q = 2
로 바꿨다고 해도 Q가 C보다 2배 크다거나 S보다 더 큰 값을 가진다는 의미는 아니다.

그런데 모델이 이 변수를 일반적인 숫자형 변수로 받아들이면 0 < 1 < 2 같은 순서나 숫자 사이의 거리에도 의미가 있다고 잘못 판단할 수 있다.

그래서 Sex나 Embarked처럼 단순한 종류를 나타내는 변수는 모델에게 범주형 변수라는 것을 알려주거나 One-Hot Encoding 같은 방법을 사용해 처리해야 한다.



### 8. 하이퍼파라미터(사람이 정하는 값)와 파라미터(모델이 스스로 배우는 값)는 어떻게 다른가?

파라미터는 모델이 데이터를 학습하면서 스스로 찾아내는 값이다.

예를 들어 Logistic Regression의 각 변수에 대한 가중치는 모델이 학습 과정에서 자동으로 결정한다.

반면 하이퍼파라미터는 학습을 시작하기 전에 사람이 직접 정해주는 설정값이다.

예를 들어

학습률(Learning Rate)
트리의 깊이(Max Depth)
트리 개수
Logistic Regression의 C 값
등이 하이퍼파라미터이다.

즉,

파라미터 = 모델이 학습하면서 결정
하이퍼파라미터 = 사람이 학습 전에 설정

이라고 이해하면 된다.



### 9. K-Fold 교차검증을 한 번만 검증하는 것보다 더 믿을 수 있는 이유는 무엇인가?

Train 데이터를 한 번만 Train/Validation으로 나누면 어떤 데이터가 Validation에 들어갔는지에 따라 점수가 달라질 수 있다.

우연히 쉬운 데이터가 Validation에 많이 들어가면 점수가 높게 나오고, 어려운 데이터가 많이 들어가면 점수가 낮게 나올 수도 있다.

K-Fold는 데이터를 K개로 나눈 뒤 Validation 부분을 바꿔가며 여러 번 학습하고 평가한다.

예를 들어 5-Fold라면 5번 평가한 뒤 그 결과의 평균을 사용한다.

따라서 한 번의 우연한 데이터 분할에 영향을 덜 받고, 모델의 실제 성능을 조금 더 안정적으로 판단할 수 있다.



### 10. 모델 여러 개의 예측을 평균 내는 앙상블이 왜 모델 하나만 쓰는 것보다 더 안정적인가?

모델마다 잘 맞추는 데이터와 틀리는 데이터가 조금씩 다르다.

예를 들어 모델 A가 어떤 승객의 생존 확률을 0.9라고 예측하고, 모델 B는 0.6, 모델 C는 0.7이라고 예측할 수 있다.

이 세 모델의 평균을 사용하면 하나의 모델이 너무 극단적으로 잘못 예측했을 때 그 영향을 줄일 수 있다.

즉 여러 모델의 의견을 합치면 각 모델의 실수를 서로 보완할 수 있다.

그래서 하나의 모델만 사용할 때보다 예측 결과의 변동이 줄어들고 더 안정적인 결과를 얻을 수 있다.
