# 과제 2

1. 결측치(missing value)란 무엇이고, 왜 그냥 두면 안 되는가?

  -> 결측치는 말 그대로 어떤 값이 빠져있는 것을 의미한다. 결측치를 그대로 두면 모델이 잘못된 방향으로 학습할 수도 있고, 오류를 발생할 수도 있다.

2. **훈련(train) 데이터와 테스트(test) 데이터를 나누는 이유**는 무엇인가?

  -> 두 데이터를 가르지 않으면 모델이 무언가를 학습해서 성적이 잘 나오는 게 아니라 단순히 답을 외우는 형태가 될 수 있기 때문이다. 

3. 과적합(overfitting)이 무엇인지, 왜 안 좋은지 예를 들어 설명해보라.

  -> 모델이 훈련 데이터를 너무 지나치게 학습한 상태이다. 어떤 학생이 학습을 한다고 가정했을 때, 학습지에 있는 모든 문제를 외우고 정답까지 외워서 푼다고 하면 이와 관련된 변형된 문제나 응용 문제는 풀지 못 하는 것과 같다.

4. **범주형 변수(categorical variable)를 숫자로 바꿔야 하는 이유**는 무엇인가? (모델이 문자를 이해하지 못하는 이유)

  -> 문제에도 적혀있듯 모델은 문자를 이해하지 못 하기 때문이다. 대부분의 컴퓨터가 그렇듯 모델 또한 많은 것을 숫자와 연산으로 이해한다.  

5. 특성 엔지니어링(Feature Engineering)이 무엇이며, 왜 원본 데이터를 그대로 쓰지 않고 새로운 변수를 만드는가?

  -> 모델에게 학습 데이터를 줄 때 원시 데이터를 그대로 주는 게 아니라 모델이 더 잘 알아볼 수 있는 형태로 만드는 것이다. 모델이 알아서 관계를 판단하는 것이 아니라 명시적으로 전처리를 해서 주면 모델이 더 쉽게 이해할 수 있다.

6. EDA(탐색적 데이터 분석)를 모델링 전에 먼저 하는 이유는 무엇인가?

  -> 모델 학습을 하기 전에 이상치가 얼마나 있는지, 결측치가 얼마나 있는지, 데이터가 어떻게 분포되어 있는지를 가볍게 알 수 있기 때문이다. 이런 데이터의 구조적 특징을 아는 것으로 모델 학습 계획을 수립할 수 있다.

7. 교차검증(Cross Validation)이 한 번의 검증(홀드아웃)보다 신뢰할 수 있는 이유는 무엇인가?

  -> 예를 들어서 검증 데이터셋에 어려운 문제가 많다고 가정한다면, 혹은 반대로 쉬운 문제가 우연히 많이 들어갔다고 하면 검증 결과가 휙휙 바뀔 수가 있다. 교차 검증을 통해서 데이터를 여러 구간으로 나눠서 검증하는 식으로 더 정확한 검증을 할 수 있다.

8. Feature Importance(특성 중요도)를 확인하면 실제로 어떤 도움이 되는가?

-> 특성 중요도는 어떤 변수, 어떤 특징이 얼마나 영향을 주는지를 알 수 있다. 특성 중요도를 보고 모델이 합리적인 추론을 하고 있는 것인지 알 수 있다. 이를 통해 새로운 특성을 만들거나 아니면 데이터 추가 분석을 어떤 식으로 할지 구상할 수 있다.
